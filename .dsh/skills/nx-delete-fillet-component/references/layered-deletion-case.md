# NX 分层删除案例参考

## 身份与证据边界

本文中的历史面号、组件号和修订号只用于审计，不是 Tool 输入。下一次操作必须从当前 `defeature_reanalyze_current_state` 获取新的状态绑定 `face_ref` 或 `segment_id`；不得跨 STEP 重新导入按相同序号映射面。

这是一次 Siemens NX2406 STEP/B-rep 受控删面案例。原始模型从 68 面删至已接受的 r1（49 面）；本文只记录从 r1 开始的详细轨迹，不补造前 10 次删除的选面记录。

## 观察到的轨迹

| 状态 | 目标与方法 | 结果 |
| --- | --- | --- |
| r1，0→1 | 112–116 五面 Face Group；`face_edge_blend + cliff` | 49→44 面；先处理此前无法闭合的大组件中的局部角点汇合。 |
| r1，1→2 | 106 与 121 两面 Face Group；`face_edge_blend + cliff` | 44→42 面；单删 106 会使 121 连带消失，回滚后根据邻接显式合组。 |
| r1，2→3 | 107、119、120、122；`face_edge_blend + notch`；`allow_related_faces=true` | 42→37 面；四目标和封口 79 消失，主体平面留存。四面 `cliff` 被连带检查回滚；显式加入 79 的五面 `cliff` 组无法闭合。 |
| r1，3→4 | 123–127 五面 B-Surface 子网；`face_edge_blend + cliff` | 37→32 面；端面 104 从余下网络分离。 |
| r1，4→5 | 独立端面 104；`face_edge_blend + cliff` | 32→31 面；发布 Candidate r2，由用户审核接受。 |
| r2，0→1 | 重新导入后完整五面叶链 90–94；`topology_branch`；`generic_face + cliff` | 31→26 面；专用 `face_edge_blend` 组合不能闭合，完整叶链的受控通用删面成功。 |
| r2，1→2 | 剩余 B-Surface 两面链 95、96；整组件；`generic_face + cliff` | 26→24 面；检测到的圆角组件为 0，圆锥和主体平面保留，发布 Candidate r3。 |

r2 重新导入后面身份重新编号；最后两步同时换用了 `generic_face`。因此不能把成功单独归因于重新导入，也不能推断这些面属于某个已知 Creator operation。

## 可迁移规则

1. 连通块不等于删除单元。优先处理有明确角点、叶链和支撑关系的局部单元；大型连通块和粗分段失败时回滚并拆分。
2. 拓扑策略拒绝是证据，不是牺牲相关面的授权。`collateral_disappeared_faces` 必须逐项核对几何角色。
3. 显式选封口面与让 NX 自动恢复封口不等价。使用 `allow_related_faces=true` 后，检查实际消失面、总面数、邻接和支撑边界；超出预期立即回滚。
4. 同一平面可能从封口转为主体支撑面。不能只按 `Planar` 类型或删除前邻接决定是否删除。
5. 专用方法失败后，可在已确认完整的混合/非标准曲面叶链上受控尝试 `generic_face`。这只改变后端，不授权无限扩大选面；圆锥、薄壁、外轮廓和确认的支撑面仍需保护。
6. 成功、回滚和重新导入后都必须重新分析并重新取得引用。旧 `face_ref`、分段 ID 和历史 STEP 面号不得复用。
7. 同一状态的失败去重键至少是“当前目标身份集合 + method + preference”；仅改变 `allow_related_faces` 不构成新的有信息尝试。

## 验证边界

本案例观察到了 NX 提交、拓扑保护、失败 Undo、逐步重分析、STEP 导出、OCC 重读和非空 BREP 面网格。当前发布门槛不包含完整 BRepCheck、单一闭合固体、正体积或局部形变硬校验。因此应表述为“NX 当前检测器显示 0 个圆角候选组件”，而不是“数学证明所有实际圆角消失且实体完全有效”。

本参考不改变生产 Tool allowlist；`generic_face` 的案例仅适用于已开放的开发模式受控流程。
