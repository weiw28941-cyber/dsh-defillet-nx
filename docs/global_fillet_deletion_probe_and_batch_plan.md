# 全局圆角删除：只探测、二分归并与动态拓扑批次执行计划

> 本计划中的根目录 `Defillet/` 对应迁移目标 `cad/Defillet/`；其余内容保留原计划事实。

## 1. 背景与目标

当前全局删除算法在每次成功删除一批后，会基于变化后的模型重新检测全部圆角并开始新一轮二分。初始 24 个组件的任务因此可能建立多棵二分树，重复测试已知困难区域，出现 82 次尝试和 12 轮检测。

本计划的目标是：

- 初始圆角组件只完整检测一次；
- 在原始模型上完成一次可删除性二分隔离；
- 探测成功或失败都立即 Undo，不保留模型修改；
- 对可删除候选进行二分归并，不因合并失败丢弃候选；
- 不设置尝试次数或耗时上限，删除质量优先；
- 最终分批删除时，基于每次 Commit 后的当前 NX 拓扑重新定位剩余候选；
- 完成后只导出一次 STEP、执行一次 OCC 验证，并发布一个 Candidate。

## 2. 基本约束

1. STEP Entity ID 只在初始导入状态中稳定。
2. 一次删除 Commit 后，NX 可能删除、拆分、合并或重建面，原 STEP ID、Face 引用和 Tag 都可能失效。
3. 因此，原始模型上的探测可以复用初始身份；最终分批执行不能直接复用初始 STEP ID。
4. 动态重检仅用于追踪“首次检测到的剩余候选”，不得把删除后新出现的圆角加入本次任务。
5. 不得以最近面、枚举顺序或不唯一的几何近似作为身份回退。

## 3. 阶段一：首次检测并固定初始候选

STEP 只导入一次，在 NX 内存模型上只进行一次完整圆角检测，得到稳定的初始组件：

```text
fc-001 ... fc-N
```

为每个初始组件保存：

- `component_id`；
- 初始 STEP Face ID；
- 初始 NX Face 引用和 Tag；
- 必要的几何与拓扑签名，供后续动态追踪。

后续不得因为成功删除而重新开始全模型候选发现。

## 4. 阶段二：原始模型上的只探测二分

### 4.1 探测语义

NX 没有足够可靠的纯只读“能否删除”接口，因此一次探测仍然临时执行 Delete Face：

```text
创建 Undo Mark
→ 临时 DeleteFaceBuilder.Commit()
→ 判断 Commit 是否成功且模型确实变化
→ 无论成功或失败都 UndoToMark()
→ 比较模型快照，确认完整恢复
```

探测不保留任何几何修改。

若 Undo 后快照不一致，立即以 `infrastructure` 类错误终止任务。

### 4.2 单棵二分树

对初始组件全集探测：

```text
全部组件
├─ 成功：整个集合成为可删除候选批次
└─ 失败
   ├─ 探测左半
   └─ 探测右半
```

规则：

- 成功节点不再拆分；
- 失败节点且元素数大于 1 时继续二分；
- 失败单组件标记为 `intrinsically_failed`；
- 相同组件集合通过规范化 Key 缓存，不重复探测；
- 不重新检测、不建立新的轮次。

标准二分隔离在 N 个初始组件下最多访问 `2N-1` 个树节点，但本方案不设置人为硬上限。

## 5. 阶段三：候选批次二分归并

第一阶段得到多个原始状态下探测成功的候选批次。先探测它们的全集：

```text
A ∪ B ∪ C ∪ D
```

### 5.1 合并成功

将全集视为一个可执行批次。

### 5.2 合并失败

不得跳过或丢弃候选，而应对候选批次集合继续二分：

```text
[A, B, C, D]
├─ [A, B]
└─ [C, D]
```

- 成功的一半保留为归并批次；
- 失败的一半继续二分；
- 直到所有原始可删除候选都被分配到某个可成功探测的批次；
- 相同集合结果继续缓存。

这一步保证合并失败不会牺牲已经确认可删除的组件。

## 6. 阶段四：最终动态拓扑批次执行

### 6.1 不采用“演练、Undo、旧身份重放”

完整演练后 Undo，再按初始 STEP ID 重放是不可靠的，因为第一次正式 Commit 后拓扑身份已经变化。

正确方式是：

```text
创建外层总 Undo Mark
→ 执行批次 1
→ 在当前拓扑上重检并定位剩余初始候选
→ 执行批次 2
→ 再次动态定位
→ ...
→ 全部成功后直接保留当前模型
```

这条成功执行链本身就是最终结果，不再 Undo 后重放。

### 6.2 动态重检范围

每批成功后允许重新枚举当前 Face、识别当前圆角候选并计算连通块，但用途仅限于：

- 查找尚未处理的初始候选在当前拓扑中的后继；
- 更新下一批实际提交给 DeleteFaceBuilder 的当前 NX Face 集合。

禁止：

- 将新出现的圆角加入本次任务；
- 重新尝试初始阶段已判定不可删除的组件；
- 清空缓存并重新建立全局二分树。

## 7. 剩余组件的动态身份匹配

匹配应综合使用：

1. 仍存活的原始 STEP 名称；
2. 删除前保存且仍有效的当前 NX Face 引用；
3. 未变化面的身份锚点；
4. 几何签名，例如曲面类型、半径、面积、质心、轴线或中心；
5. 拓扑签名，例如 Face 数量、共享边关系及支撑面邻接；
6. 已删除批次与剩余候选的排除关系。

匹配必须唯一、可验证。若出现多个候选或身份不完整，则当前执行顺序失败，整体回滚；禁止使用最近点或枚举顺序强行匹配。

报告中应记录初始组件到当前组件的映射：

```json
{
  "original_component_id": "fc-003",
  "current_component_id": "state-02-fc-005",
  "match_method": "surviving-face-and-topology-signature"
}
```

## 8. 拓扑合并与拆分处理

### 8.1 一对一

一个初始组件唯一对应一个当前组件，正常继续。

### 8.2 多对一

多个剩余初始组件在当前拓扑中合并成一个组件：

- 将它们视为一个当前批次；
- 在当前模型状态中进行临时探测；
- 成功后执行，失败则对对应初始候选集合继续二分。

### 8.3 一对多

一个初始组件拆分成多个当前组件：

- 将当前子组件视为该初始组件的后继集合；
- 在当前状态中二分探测可行组合；
- 目标仍是覆盖该初始候选的全部可删除后继。

### 8.4 无法唯一匹配

标记 `identity_conflict`，回滚完整执行顺序并尝试其他批次顺序。

## 9. 顺序搜索与失败恢复

一个批次在原始模型中成功，不保证在前序删除后仍成功。因此最终阶段需要搜索可行顺序。

确定性顺序建议：

1. 面数较大的批次优先；
2. `component_id` 作为次级排序；
3. 二分时左侧优先；
4. 某批次受前序删除影响失败时，尝试将其提前；
5. 对冲突批次继续二分。

每个完整顺序都放在外层总 Undo Mark 下：

- 全部成功：保留模型；
- 中途几何失败或身份冲突：Undo 到总 Mark，验证原始快照恢复，然后尝试新顺序。

缓存键至少包含：

```text
当前模型状态摘要 + 剩余初始组件集合 + 当前批次或执行顺序
```

同一状态下的相同失败尝试不得重复。

## 10. 质量优先与终止条件

不设置总尝试次数或总耗时上限。算法仅在以下条件终止：

- 找到覆盖全部候选组件的可执行顺序并完成删除；
- 证明某些初始组件在原始状态中就不可删除；
- 对候选组件的所有确定性批次划分与顺序均已探索，仍存在 `order_conflict`；
- 发生基础设施、Undo 完整性或身份唯一性错误。

“无上限”不等于允许重复工作；集合缓存、状态缓存和顺序缓存必须阻止重复尝试。

## 11. 最终输出与 Candidate 生命周期

成功完成最终批次链后：

```text
当前 NX 内存模型
→ STEP 导出一次
→ OCC 重导入与三角化一次
→ 创建一个 Revision
→ 发布一个 Candidate
```

如果没有任何候选可删除，或最终执行整体失败：

- 不导出最终 STEP；
- 不运行 OCC；
- 不创建 Revision；
- 不发布 Candidate；
- Accepted Revision 保持不变。

## 12. 报告结构建议

```json
{
  "initial_component_count": 24,
  "probe_attempts": [],
  "probe_cache_hits": 0,
  "candidate_component_ids": [],
  "intrinsically_failed_component_ids": [],
  "merge_batches": [],
  "execution_sequences": [],
  "identity_transitions": [],
  "order_conflict_component_ids": [],
  "final_execution": {
    "status": "succeeded",
    "commit_count": 3,
    "all_candidate_components_deleted": true
  }
}
```

探测记录必须明确：

- `status`；
- `rolled_back: true`；
- 原始组件集合；
- 当前模型状态摘要；
- 是否命中缓存。

正式执行记录必须明确当前拓扑身份，不得把“请求的原始 STEP ID”误报为“实际删除的当前面”。

## 14. 验收标准

1. 初始全模型组件只检测一次；
2. 原始状态二分探测无论成功或失败都 Undo；
3. 不再因成功删除而开启新的全局检测轮次；
4. 相同集合和相同状态下的尝试不重复；
5. 合并失败后继续二分，候选组件不被直接丢弃；
6. 不设置尝试次数或耗时上限；
7. 最终批次执行后使用当前 NX 拓扑重新定位剩余候选；
8. 不直接复用失效的初始 STEP ID、Face 引用或 Tag；
9. 身份匹配不唯一时安全回滚；
10. 成功执行链直接成为最终结果，不 Undo 后重放；
11. 所有候选组件都被删除，或报告经过确定性搜索确认的不可删除/顺序冲突原因；
12. STEP 只导出一次；
13. OCC 只重导入和三角化一次；
14. 最终只发布一个累计 Candidate。
