# NX 圆角分层删除案例与 Skill 更新交接文档

> 本记录中的 `NXPersistentWorker/worker.py` 对应现在的 `cad/nx_persistent_worker.py`。

## 1. 用途与证据边界

本文记录一次 Siemens NX2406 对 STEP/B-rep 模型的受控删面轨迹，供后续有权限的 Agent 提炼并更新 Skill。本文不是可直接照抄的操作脚本，也不定义固定删除顺序。

文中的 `DSH_STEP_FACE_*`、组件号和修订号只属于当时的历史 NX 状态，用于审计和复盘。下一次操作必须重新获取当前状态的 `face_ref` 或 `segment_id`；不得把本文面号、组件号或修订号直接提交给删除 Tool，也不得跨 STEP 重新导入后按相同序号映射面。

原始模型曾从 68 面删至已接受的 r1（49 面）。这一阶段有 10 次成功的受控删除，但本文没有它们的逐步选面记录，不补造轨迹。以下详细记录从 r1 开始。

## 3. 失败与回滚带来的判断

### 3.1 连通块不等于删除单元

r1 的大型圆角连通块、粗二分及若干扩大的面组都遇到 NX“剩余面无法封闭”错误并回滚。成功路径依赖有明确角点、叶链和支撑关系的局部单元。

### 3.2 拓扑策略拒绝是证据，不是授权

单删 106 使角点 121 连带消失，促使核对后采用两面 `MUST_GROUP`。四面上缘链会连带消融平面 79，但不能仅凭“NX 想删它”就认定平面可牺牲：先核对其三边封口形态与邻面，再尝试不同方法。

### 3.3 显式选择封口与让 NX 自动恢复封口不同

将 79 显式加入 `cliff` 删面组反而无法闭合；仅选圆角链、采用 `notch` 后成功。`allow_related_faces=true` 是布尔放宽，不会在工具层把连带消失限定为指定面 ID。成功后仍需核对实际消失面、总面数和支撑边界，超出预期立即撤销。

### 3.4 同一平面可能改变角色

同一平面可能先近似圆角网络内的封口，之后在五面叶链删除后扩展并连接主体平面与圆锥，成为必须保留的支撑面。不能只根据 `Planar` 类型或删除前邻接决定它是否可删。

### 3.5 切换方法不等于无限扩大选面

r1 最终状态中，单末端、父层两面、五/六/七面组及含平面封口的组，若干 `face_edge_blend` 试删仍不能闭合。r2 的突破是对拓扑完整的五面叶链试受控 `generic_face`，随后再删两面链；没有把圆锥、薄壁或已变为支撑的平面一并删除。本例成功不构成其他模型的固定优先级。

### 3.6 每步重新取得引用

成功删除或回滚后必须重分析；用户接受 r2、重新建立 NX 基线后也必须重新取得面身份。旧状态的 `face_ref`、分段 ID 和历史 STEP 面号不得复用。同一状态下的失败去重键应是“目标身份集合 + method + preference”；仅改变 `allow_related_faces` 不能重试同一失败组合。

## 4. 建议提炼到 Skill 的可迁移规则

后续 Agent 应将以下内容提炼成规则，而不是把本案例表格复制成固定执行顺序：

1. 在 `fillet-removal-strategy` 的耦合面处理处增加：封口面必须依据当前邻接和受控试删判断；显式加入 Face Group 可能与允许 NX 自动恢复产生不同结果；每次删除后重新判断其是否已转为主体支撑。
2. 在 `nx-delete-fillet-component` 的失败回退、Face Group 与成功后处理中增加：对 `collateral_disappeared_faces` 先核对几何角色；使用 `allow_related_faces=true` 后逐项检查实际连带范围，不符立即撤销；失败去重不包含该布尔开关；混合非标准曲面的完整叶链可在先前方法失败后尝试受控 `generic_face`。
3. 将本案例另存为相关 Skill 的独立 reference，并从策略 Skill 与执行 Skill 链接。reference 开头须明确：所有历史面号只供审计，不是 Tool 输入。
4. 不改变生产 Tool 的 allowlist，不将开发模式的 `generic_face` 案例误写为生产模式已有能力。

## 5. 验证边界

本次受控操作观察到了 NX 提交、拓扑保护、失败 Undo、逐步重分析，以及发布时 STEP 导出、OCC 重读和非空 BREP 面网格。当前发布实现以 `faceCount > 0` 等条件为门槛，不包含完整的 BRepCheck、单一闭合固体、正体积或局部形变硬校验。

因此交付表述应为：

> NX 当前检测器显示 0 个圆角候选组件。

不要表述为“已数学证明所有实际圆角消失且实体完全有效”。如实体级检查是下游必需，应作为独立 Tool 增强任务实现。
